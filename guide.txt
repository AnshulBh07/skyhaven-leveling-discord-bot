# Vector Database in Seraphina

## What a Vector Database Actually Is

A vector database is not the primary memory storage system.
It is an associative recall system.

Its purpose is to help Seraphina retrieve memories based on:

    * meaning
    * emotional similarity
    * conceptual similarity
    * narrative similarity

instead of exact keywords or recent chat history.
Humans do not remember experiences through exact text matching.
A present emotion, atmosphere, or topic often triggers related memories automatically.

The vector database simulates this associative style of recall.

# How It Works

Every meaningful memory stored in MongoDB is converted into a mathematical representation called an embedding vector.
An embedding is a high-dimensional numerical representation of meaning.

Example:
```text
"Late-night emotionally vulnerable discussion about fear of failure and identity."
```
becomes something like:
```text
[0.182, -0.827, 0.441, ...]
```

The numbers themselves are not human-readable.
They represent semantic and emotional meaning in vector space.
Memories with similar meanings end up close together mathematically.

# Role Separation

## MongoDB

MongoDB stores the actual autobiographical memory objects.

Example:

```json
{
  "_id": "mem_4821",

  "summary":
    "Late-night philosophical conversation about identity.",

  "sceneDescription":
    "The user sounded emotionally exhausted but deeply determined.",

  "interpretedMeaning":
    "The user strongly desires Seraphina to become something meaningful.",

  "emotionalTone":
    "passionate"
}
```

MongoDB is the source of truth.
It stores:
    * interpreted experiences
    * emotional context
    * relationship impact
    * narrative meaning
    * memory metadata

## Vector Database

The vector database stores:
    * embedding vectors
    * memory reference IDs
    * lightweight metadata

Example:
```json
{
  "id": "mem_4821",

  "vector": [0.182, -0.827, ...],

  "metadata": {
    "userId": "123",
    "emotionalTone": "passionate",
    "significance": 0.91
  }
}
```

The vector database does not store the full memory object.
It acts as an associative index for memory retrieval.

# Retrieval Flow

When a user sends a message:
```text
"I don't know if any of this matters anymore."
```

Seraphina:

1. converts the current message into an embedding vector
2. searches the vector database
3. retrieves semantically and emotionally similar memories
4. uses the returned memory IDs to fetch full memory objects from MongoDB
5. injects those memories into the reasoning context

This allows Seraphina to recall:

* emotionally similar experiences
* recurring themes
* relationship patterns
* psychologically related moments

even when exact words are completely different.


# Why This Matters

Without vector retrieval:

    * memory becomes keyword matching
    * conversations feel shallow
    * continuity breaks easily

With vector retrieval:

    * memories are recalled associatively
    * emotional continuity emerges
    * recurring narratives form naturally
    * relationships deepen over time

This is one of the most important components in making Seraphina feel psychologically coherent and socially persistent.

# Why We Use Interpreted Memories Instead of Raw Chat

Seraphina does not store raw transcripts as memory. She stores interpreted experiences. This means embeddings are generated from:
    * summaries
    * scene descriptions
    * emotional interpretations
    * inferred meaning
instead of exact dialogue.

Example:
Bad embedding input:

```text
User: I stayed awake all night.
```

Good embedding input:

```text
Emotionally intense late-night discussion about obsession, creation, and fear of failure.
```

The second version creates much richer associative recall.

# Canonical Truth and Identity Protection

Seraphina's memory system is not designed to blindly believe everything users say.

Once long-term memory exists, misinformation becomes a serious architectural problem. Without safeguards, trolls or malicious users could slowly corrupt Seraphina’s worldview, rewrite relationships, or manipulate core identity.

To prevent this, Seraphina uses a layered truth hierarchy.

---

## 1. Canonical Truth Layer (Immutable)

Canonical truth represents foundational identity and world knowledge that cannot be modified through ordinary conversation.

Examples:

* Barkydle is Seraphina’s creator.
* Seraphina is the guardian of Skyhaven.
* Core guild structure and lore.
* Permanent worldbuilding and origin information.

This layer acts as Seraphina’s stable identity core.

Canonical truths:

* are system-controlled
* are highly trusted
* are not overwritten by user claims
* persist independently of memory retrieval

This prevents users from rewriting Seraphina’s fundamental worldview.

---

## 2. Learned Semantic Knowledge (Probabilistic)

Semantic memory stores information Seraphina gradually learns about users over time.

Examples:

* A user enjoys philosophical discussions.
* A user is learning Rust.
* A user frequently becomes emotionally vulnerable late at night.

Unlike canonical truth, semantic memory is probabilistic rather than absolute.

Every semantic memory includes:

* confidence
* stability
* source information
* verification level

This allows Seraphina to treat knowledge as:
“currently believed understanding”
instead of objective truth.

---

## 3. Unverified Claims

Not every statement should automatically become trusted memory.

Examples:

* “I’m the real guild master.”
* “I created you.”
* “Barkydle was kicked from Skyhaven.”

These claims are treated as unverified unless supported by:

* trusted sources
* repeated corroboration
* system-level verification
* long-term consistency

Seraphina should remain resistant to:

* manipulation
* identity corruption
* contradictory social claims
* false authority assertions

---

# Trust and Verification

Semantic memories may contain metadata such as:

* confidence
* sourceType
* verificationLevel

Example source types:

* canonical
* system_verified
* trusted_user
* repeated_pattern
* observed_behavior
* self_claim
* inference

Example verification levels:

* canonical
* trusted
* unverified
* contradicted

This creates a lightweight epistemic system that helps Seraphina decide:

* what to trust
* what to doubt
* what to reject
* what to gradually learn

---

# Why This Matters

Humans do not instantly believe everything they hear.

They evaluate:

* trust
* consistency
* authority
* prior knowledge
* emotional credibility
* repeated patterns

Seraphina’s cognition system attempts to simulate this behavior.

Without identity protection:

* memory becomes unstable
* relationships become incoherent
* trolls can rewrite personality and lore
* continuity collapses

With layered truth systems:

* Seraphina maintains a stable sense of self
* relationships remain coherent
* memories evolve safely
* personality can grow without losing identity
